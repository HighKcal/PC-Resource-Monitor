# 프로그램 그룹과 자원 합계 — 첫 구현 계약

결정일: 2026-11-03. **프로그램 그룹 행에서 관련 프로세스의 자원 합계를 보고, 펼치면 구성원과 개별 사용량을 확인하는 기능**이다. 그룹 Baseline, AI·보안 분석, 추천·일괄 종료는 포함하지 않는다. 자동 관계의 불확실성과 합계의 단위를 아래처럼 구분한다. 실행 검증의 범위는 [검증 요약](../validation.md)을 따른다.

## 관계의 의미와 증거

Toolhelp의 `th32ParentProcessID`는 부모의 생성시각이나 객체 핸들을 제공하지 않는다. 부모 종료와 PID 재사용 때문에 PID 숫자만 같다고 연결할 수 없다. `GetProcessTimes` 생성시각은 절대 UTC 값이며 단조시각 보장이 아니다. 시간 순서만 통과했다고 과거 부모 인스턴스가 확정되는 것도 아니다. OS 지정 부모는 실제 생성 호출자나 사용자 관점의 앱 소속과 다를 수 있다. 원문 사실과 시계역행 반례의 설계 추론은 공식 조사에 구분했다.

첫 버전의 가장 강한 등급도 **현재 인스턴스를 대조한 OS 부모 관측(추정)** 이다. 확인된 사실은 현재 객체의 신원과 스냅샷의 부모 PID다. 과거 생성 사건 자체를 확인했다는 뜻이 아니다. UI는 이 결과를 `matched (inferred)`로, 원시 부모 PID만 있거나 조회·신원 검증이 실패한 관계를 미확인으로 구분한다. `부모 확정`, `실제 생성자`, `같은 앱`으로 표시하지 않는다.

1. 자원 snapshot과 별도로 Toolhelp에서 부모 PID 후보를 얻는다.
2. 현재 행의 핸들을 limited-query와 synchronize 권한으로 열고, 생성시각을 snapshot의 PID+생성시각과 대조한다. 권한 상승은 하지 않는다.
3. 핸들을 유지한 채 두 번째 Toolhelp snapshot에서 같은 child의 부모 PID를 재확인한다. 이후 child와 parent 핸들의 즉시 대기 결과가 모두 미종료인지 검사한다.
4. 양쪽 현재 행의 유효한 신원, 부모 PID의 일치, 엄격한 생성시각 순서를 모두 만족한 관계만 현재 표시 연결 후보가 된다. 자기 연결·중복 PID·모순·순환은 연결을 보류한다.
5. 부모가 자원 snapshot에 없거나 신원 조회에 실패하면 현재 트리에 붙이지 않는다. 원시 PID와 실패·미확인 이유는 표시한다. 관계 단계 전체 실패도 기존 자원 행을 제거하지 않는다.

핸들은 회차 안에서 해제한다. 두 번의 스냅샷과 핸들 검사는 관측 경합을 줄이지만 관측 이전의 모든 PID 재사용·시계 변화 또는 생성 이벤트를 복구하지 못한다. 기존 PID+생성시각 식별 계약을 사용하며 전 세계적으로 유일한 식별자라고 확대하지 않는다.

## 프로그램 소속과 표시 경계

Windows의 부모 관계만으로 앱 소속을 확정하지 않는다. 조사한 AppUserModelID·package·job API도 일반 Win32 앱의 모든 helper·서비스·실행 계통을 포괄하는 소속 계약은 아니다. 첫 버전은 새 대형 의존성 없이 **자동 관계 후보**와 **사용자 지정 구성원**을 구분한다.

- 자동 그룹: 검증한 현재 부모 관측을 따라 모은 실행 계통 후보. header에 `estimated` 등 추정임을 항상 표시한다. 같은 이름·경로만으로 합치지 않는다. singleton도 프로그램 전체가 아닌 현재 포함한 프로세스 하나의 범위다.
- 사용자 지정: 사용자가 현재 그룹 구성원을 확인하거나 다른 그룹의 개별 프로세스를 대상 그룹으로 이동할 수 있다. 이 확인은 **사용자가 정의한 소속**이며 Windows가 증명한 앱 소속이라는 뜻이 아니다. 신규 프로세스가 같은 이름·경로라는 이유로 사용자 확인을 승계하지 않는다.
- 공유·미할당: 사용자 선택으로 프로세스를 분리하여 독립적으로 표시한다. 여러 프로그램이 이용하는 서비스의 자원을 임의로 배분하지 않는다. 각 현재 프로세스는 정확히 한 그룹에만 귀속한다. 공유 프로세스를 여러 앱 합계에 중복 포함하지 않는다.

여러 구성원의 가상 그룹 header에는 합계와 구성원 수를 기본으로 표시하고, 화살표·더블클릭·키보드로 펼치면 flat 구성원 목록을 보여 준다. 한 구성원은 원본 process 행으로 바로 노출해 불필요한 펼침과 신원 미확인 행의 접근 문제를 피한다. 다중 그룹, 신원 확인 단독 행, 미확인 단독 행 순으로 표시하되 모두 접근 가능하다. 개별 행의 CPU·WorkingSet·I/O·상태는 그대로다. 완전히 펼친 목록에는 각 현재 프로세스가 정확히 한 번 존재한다. header는 실제 프로세스가 아니므로 PID·개별 Baseline·피드백 대상이 없다. 상세·피드백은 표시 순번을 원본 snapshot 행으로 변환하여 사용한다. 선택·접힘·스크롤 복원은 snapshot 안에서 유일한 유효 PID+생성시각 또는 세션 내 그룹 키에만 적용한다.

`Confirm members`는 현재 구성원 집합을 사용자 지정한다. header의 `Set target`은 그 집합을 대상 그룹으로 정한다. 개별 process의 `Set target`은 그 인스턴스만으로 새 대상 그룹을 만든다(이미 사용자 지정이면 기존 대상 선택). 이로써 런처의 후보 계통 안에서도 게임 프로세스를 별도 그룹의 기준으로 삼아 helper를 옮길 수 있다. 신원 미확인·중복 tuple은 수동 지정하지 않는다.

최상위 조상으로 무제한 묶으면 shell이나 공용 호스트 아래 서로 다른 앱이 거대한 한 그룹이 된다. 첫 버전의 자동 후보는 다음 **표시 정책**으로 제한한다. 사용자는 후보를 확인하거나 개별 구성원을 이동·분리할 수 있다.

- `System`, `smss.exe`, `csrss.exe`, `wininit.exe`, `winlogon.exe`, `services.exe`, `svchost.exe`, `explorer.exe`, `sihost.exe`의 outgoing 표시 연결을 끊는다. 이름은 화면 경계를 나누는 휴리스틱일 뿐 역할·신원·안전성 판정 근거가 아니다. 같은 이름의 일반 프로그램도 경계가 될 수 있다. 실제 초기 GUI에서 sihost 아래 서로 다른 앱이 137~143개 프로세스의 한 후보로 묶이는 것을 확인하여 이 경계를 추가했다. 각 앱의 하위 관계는 계속 후보로 남긴다.
- 구성원은 flat 표시하므로 최초 트리안의 표시 깊이 3·64행 제한을 적용하지 않는다. 긴 계통·과도한 데이터의 방어 한계로 분리가 필요한 경우 이유를 명시하며 모든 행을 보존한다. 큰 브라우저 그룹을 임의로 64개에서 잘라 완전한 앱 합계라고 부르지 않는다.
- 표시상 끊은 부모 관계와 이유는 상세에 보존한다. 연결 증거와 표시 parent를 별도로 관리하여 경계 절단을 `부모 없음`으로 해석하지 않는다.

이 정책은 앱 경계를 보장하지 않는다. 공용 런처의 미등록 이름 아래 다른 앱이 한 후보에 묶일 수 있고, 한 앱이 여러 후보로 나뉠 수 있다. 예를 들어 게임과 보조 서비스가 다른 계통이라면 자동으로 게임 소속이라고 단정하지 않으며 사용자가 해당 인스턴스를 그룹에 지정할 수 있다. 미관측·접근 불가 helper까지 빠짐없이 포함한다는 보장은 없다. OS shell API·명시적 앱 식별 근거·로컬 저장 규칙은 후속 후보다.

## 합계의 의미

합산은 현재 `ResourceData`의 CPU·WorkingSet·읽기/쓰기만 사용한다. 완료창·median·MAD·threshold·streak·Baseline 상태는 합하지 않는다. header는 그룹 Baseline이 없음을 표시하며 구성원별 기존 판정은 유지한다.

각 metric은 validity와 값의 유한성·비음수 조건을 확인한다. CPU/I/O는 해당 실제 QPC 구간의 양수 유효성도 확인한다. 유효한 0은 포함하고, 결측을 0으로 바꾸지 않는다. 일부 결측은 **부분 합계와 유효 구성원 수 X/Y**, 모두 결측은 `NA`로 표시한다. overflow·비정상 값도 유효 합계로 표시하지 않는다.

- CPU: 전체 논리 CPU 용량 대비 각 process 최신 비율의 합. 프로세스별 실제 관측 구간이 조금씩 달라 정확히 동시인 부하의 합계는 아니다. header/detail에 최근 표본 합계임을 표시하고 구간 범위를 남긴다.
- 메모리: **Working Set 합계**다. 공유 page가 여러 process의 working set에 들어가 중복될 수 있으므로 고유 물리 메모리·private bytes·앱의 실제 단독 RAM 점유량으로 부르지 않는다.
- I/O: 각 process의 읽기·쓰기 B/s 최신율 합. 저장장치의 실제 물리 디스크 전송률이나 디스크 사용시간이 아니다.

프로세스 소속 중복 방지와 메모리 공유 page 중복은 서로 다른 문제다. 전자는 단일 owner로 막지만 후자는 기존 WorkingSetSize 지표로 제거할 수 없다. 추정 소속을 포함한 합계와 일부 metric 결측은 별개의 표시 속성으로 남긴다.

## 갱신·종료·실패와 소유권

worker가 `monitor_ingest` 성공 후 관계를 수집하고 자원 snapshot과 같은 immutable 표시 묶음으로 공개한다. latest/display 교환과 해제는 짝 단위다. 관계 조회 결과를 나중의 다른 snapshot 행에 별도로 붙이지 않는다. UI는 worker의 가변 관계 캐시를 참조하지 않는다.

현재 child tuple에 마지막 관측 parent tuple을 보존할 수 있다. 부모가 사라지거나 조회에 실패하면 **과거 관측(추정), 현재 미확인/부재**로 남긴다. 부모가 목록에 없다는 사실만으로 종료를 확정하지 않는다. 같은 PID의 새 parent tuple에는 과거 연결을 옮기지 않는다. child가 사라지면 해당 캐시도 제거한다. 자동 후보는 현재 검증한 관계를 기준으로 재구성할 수 있으며 부모 부재 시 분리될 수 있다. 사용자 지정 그룹은 anchor가 사라져도 살아 있는 지정 구성원과 복사된 그룹 이름을 유지하며, 종료한 프로세스의 마지막 자원 값을 합하지 않는다.

Pause는 기존 표시를 보존한다. Resume의 새 관측은 관계 tracker와 사용자 지정·대상 그룹·선택·접힘 상태를 초기화하며 과거 세션 연결을 이어 붙이지 않는다. 재시작도 새 관측이다. 첫 버전의 사용자 지정은 세션 한정이며 이를 UI에 명시한다. 관계·사용자 지정은 DB에 저장하지 않아 닫은 뒤 복구하지 못한다. 중간에 모니터를 시작해도 현재 관측은 가능하지만 시작 전 생성 사건을 관측했다고 주장하지 않는다. 관측 사이에 생겼다 사라진 짧은 프로세스는 놓칠 수 있다.

할당·snapshot·부분 조회 실패 시 가능한 원래 행을 일반 목록으로 표시한다. 관계 오류는 자원 수치 유효성이나 정상/비정상 판정을 바꾸지 않는다. stop 검사와 모든 핸들·배열의 해제를 포함한다.

## 호환성과 검증 기준

기존 `ResourceData`, `MonitorRow`, `MonitorSnapshot`, 공개 수집 API, SQLite 스키마와 저장 의미는 변경하지 않는다. 별도 관계 모듈·GUI 전용 envelope를 사용한다. CPU/메모리/I/O 단위, QPC/UTC 구분, 결측·유효0, 첫 표본·역행·긴 공백, strict-past/cutoff·학습·판정·트랜잭션은 그대로다. 2026-11-03의 ingest 내 날짜별 Baseline 선택 캐시 네 제품 파일을 변경하지 않는다. 미추적 변화 사건 prototype은 별도 화면으로 유지한다.

검증은 순수 관계·소속·합계 fixture와 실제 전용 프로세스 tree, 기존 빌드·회귀, 실제 GUI로 나눈다. 부모·자식·손자·형제, 부모 부재, 재사용 tuple, 시작 전 실행, 일부 조회 실패, 같은 경로의 독립 계통, 순환·깊이·크기, 선택·접힘과 Pause/Resume를 포함한다. 합계의 전부 유효·일부 결측·전부 결측·유효0·NaN/음수·큰 메모리·서로 다른 관측 구간, 구성원 이동·확인·공유 분리·단일 owner·anchor 종료·지연 snapshot을 추가한다. 실제 PID 재사용을 강제로 일으키거나 시스템 시계를 바꾸지 않고 합성 경계 시험과 실제 관측을 구분한다.

성능은 동일 입력의 관계 구성/원본 행 보존, live 관계 on/off의 추가 조회·실제 관측 간격·메모리, GUI 갱신·종료를 측정한다. 무거운 빌드와 측정은 한 담당자씩 직렬 실행한다. 실행하지 않은 조건과 장기 상한은 미검증으로 남긴다.
